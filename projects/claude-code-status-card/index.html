🔔 Claude Code Status Card

What if you could tell which Claude Code session needs you without alt-tabbing through all of them?

如果你不用切視窗，就知道哪個 Claude Code session 在等你呢？

1The problem問題

With several Claude Code sessions open, I kept losing track of which one had finished and which was quietly stuck waiting on me.

同時開著好幾個 Claude Code session 時，我老是搞不清楚哪個已經跑完，哪個正默默卡在那邊等我。

2My solution我的解法

One always-on-top card per session. Blue is working, red means "come here", green is done. Click a card to jump to that repo's VS Code window, and a sound plays when something changes. Each repo gets its own animal and each session its own color, which is unnecessary and I stand by it. It's fed by global Claude Code hooks, so it doesn't care which editor you use.

每個 session 一張置頂小卡。藍色是工作中，紅色代表「快過來」，綠色是完成。點一下卡片就跳到那個 repo 的 VS Code 視窗，狀態改變時還會有音效。每個 repo 有自己的動物、每個 session 有自己的顏色，這完全沒必要，而我堅持。它由全域的 Claude Code hooks 驅動，所以不在乎你用哪個編輯器。

3Challenges & fun stories挑戰與趣事

Favorite bug: log rotation briefly left an empty file, the widget read that as "start over", and dead sessions came back to life. I was, technically, the necromancer. The fix was an atomic rename.

最愛的 bug：日誌輪替時短暫留下一個空檔案，小工具把它解讀成「重新開始」，於是死掉的 session 全都復活了。嚴格來說，我是那個死靈法師。修法是原子性的改名。

Another: sessions started from different subfolders counted as different repos, so one real project showed up as nine entries with nine icons. Now it walks up to the project root. And on Windows, Claude Code's hook layer eats backslashes in paths, which took an embarrassing amount of time to figure out.

另一個：從不同子資料夾啟動的 session 會被當成不同的 repo，於是一個真實專案變成九筆紀錄、九個圖示。現在它會往上找到專案根目錄。還有在 Windows 上，Claude Code 的 hook 層會吃掉路徑裡的反斜線，這個問題花了我尷尬的時間才搞懂。

Known issue: the red "needs approval" state is inferred rather than signalled, and it's been unreliable since Claude Code defaulted to Auto mode. Turns out the best way to fix approval prompts is to have fewer of them.

已知問題：紅色的「需要核准」狀態是推測出來的，不是被通知的，而自從 Claude Code 預設改成 Auto 模式後，它就不太可靠了。看來修好核准提示的最佳方法，就是讓它們變少。

4Tech stack & what I learned技術堆疊與我學到的

ElectronNode.jsClaude Code hooksPowerShell

SaaS cannot be done in one day. I learned how hooks work and how to tell repos apart by reading hooks alone. And grinding out improvements took weeks, as a real user of my own tool. Day one I realized I couldn't recall which session was named what. Day two the icons were inconsistent across sessions. Day three I noticed I was still keeping an eye on my monitor, just not alt-tabbing anymore, so I added sound effects on top of the state changes.

SaaS 不可能一天做完。我學會了 hooks 怎麼運作，也學會只靠讀 hooks 就分辨不同的 repo。而且身為自己工具的真實使用者，打磨改進花了好幾個星期。第一天我發現我記不得哪個 session 叫什麼名字。第二天我發現各個 session 的圖示不一致。第三天我發現自己雖然不再切視窗了，卻還是一直盯著螢幕，所以我在狀態變化之外又加了音效。
